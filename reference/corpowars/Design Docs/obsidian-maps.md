# Obsidian Maps: how Corpo Wars sites are built

Status (2026-09-27): **industrial sites are live on Obsidian.** These are warehouses, sea docks, fab plants, power plants, substations, industrial parks, salvage yards and construction sites. The other site types still use the in-engine kits (site-kits.md) or, for offices, the G02 generator. They move over one at a time.

## 1. The idea

Obsidian, the Doom level generator, builds the maps. The game doesn't generate architecture any more; it only runs the mission on top.

- An Obsidian **addon** called `CorpoWars` turns Obsidian into our site generator. It supplies our themes and textures, switches off combat, names the maps for the pool, and leaves markers behind.
- The **launcher** (`Play_CorpoWars.bat` → `CorpoWars_Launcher.ps1`) keeps a **pool** of maps for each site type. It runs Obsidian in batch mode and loads the pools with the game.
- The **game** (`obssite.zs`) reads the markers when a pool map loads. It converts the doors, defuses the exits, and adds lamps, furniture, objectives, guards, bystanders, extraction and the drop crate. Then it inserts the player.

Files:

| Where | What |
|---|---|
| `CorpoWars_tools/obsidian_addon/CorpoWars/modules/corpowars.lua` | the addon: hooks, texture swap, markers, quality gate |
| `.../modules/corpowars_sites.lua` | **one table per site type**: map names, theme, room themes, roles, palette, forced styles, QA rules. This is the file to tune. |
| `.../modules/corpowars_textures.lua` | every Corpo Wars texture (generated by `obsidian_textures.py`) |
| `.../presets/CorpoWars Industrial.txt` | the Obsidian settings for the industrial pool (size, length, modules) |
| `CorpoWars_Launcher.ps1`, `Play_CorpoWars.bat` | pool upkeep and game start |
| `CorpoWars_pool/` | the pools: `cw_pool_<site>_<set>.pk3`, `next/` (built in the background), `launcher_log.txt` |
| `CorpoWars/zscript/corpowars/obssite.zs` | the in-game side (markers, doors, mission) |

The launcher copies the addon into `Obsidian/addons/CorpoWars` on every start, so edit the copy in `CorpoWars_tools`.

## 2. The pool

- **Each site type has two map-name sets.** Industrial uses `CWI01`–`CWI32` and `CWJ01`–`CWJ32`; MAPINFO defines both. A pool is one Obsidian "episode" of 11 maps, zipped into `cw_pool_industrial_CWI.pk3`, about 2.5 MB.
- **First launch:** if a site has no pool, the launcher builds one before the game starts. That takes about 1–2 minutes, because the quality gate rebuilds weak maps.
- **Every launch:**
  1. If a pool was built in the background last time (`CorpoWars_pool/next/`), it is swapped in first.
  2. The game starts with every pool loaded, and `+set cw_pool_industrial <set>` names the current set.
  3. A background PowerShell then builds a new pool for the site whose pool is oldest. It always uses the other map-name set.
- **Why two sets:** the previous pool stays loaded. Saves made on an old map, and job offers that point at one, keep working after a new pool arrives.
- **Which map a job gets:** `CW_ObsSite.PoolMap(set, seed)`. A corp property always gets the same map while a pool lasts, because it has a fixed seed. A new pool "renovates" it. Neutral sites land anywhere in the pool.
- **Fallbacks:**
  - If a site has no pool maps at all, jobs use the in-engine kit (K03).
  - `cw_obsidian 0` turns the pool off.
  - `cw_kitsites 0` puts everything back on G02.
- **Launcher options:**
  - `Play_CorpoWars.bat -Rebuild` builds fresh pools now.
  - `-NoBuild` plays what's there.
  - `Play_CorpoWars_Debug.bat` also writes `cw_debug_log.txt`.

## 3. The addon: what it changes in Obsidian

- **Themes.** Each site is an Obsidian level theme (`cw_industrial`). It is built by copying a base theme (`tech`) and laying our fields over it: facades, fences, liquids, hallway groups, style probabilities. Room themes are named `cw_industrial_<Name>` and each carries a `cw_role`.
- **Prefabs.**
  - Our themes may use the base theme's prefabs, plus any prefab tagged `theme = "cw"` or `"cw_<site>"`.
  - Start pads, exit closets, item pedestals, switch closets, cages, traps and teleporters are never built (they came with bars, lifts and switches). Decoration never goes in hallways. Anything named cross, gothic, skull, hell, altar, church… is dropped whatever its kind; a theme group left with no prefabs is forgotten.
  - Windows are open kinds only (no bars, cages or crosses), and they're passable except at the map's scenery edge.
  - Decorative prefabs whose names suggest hell, gore, candles, trees, cages, traps and so on are dropped.
  - Structural ones (windows, doors, halls, stairs) are never dropped, because Obsidian needs a match for every slot.
- **Texture swap.** Every material lookup goes through the site palette, so no Doom texture survives, even one a prefab hard-codes.
  - Walls are sorted by name into door, trim, light, machine, step, brick, wood, metal or concrete.
  - Flats are sorted into light, ceiling, grate or floor.
  - Liquids become water. Railings (`MID*`) and the sky stay.
- **No combat.** No monsters, no pickups, no keys, switches, traps, cages, secrets, ambushes or teleporters. Doors are set to "heaps". Only player starts, our markers and our prop things get into the map. Doom lamps become lamp markers.
- **Night.** Outdoor light is fixed at 144 (industrial).
- **Only maps in the WAD.** Titles, MAPINFO, DEHACKED, sky and texture lumps are all switched off.
- **Map names** come from the pool option `cw_pool` (`CWI` / `CWJ`).
- **Quality gate.** After each map is built, its markers are counted. Industrial needs at least 9 rooms, 5 buildings, 1 outdoor area and 3 entries. Anything less is built again using Obsidian's own retry loop, which keeps the last try after three attempts.

### Markers (the map contract)

| Thing | Meaning | Angle |
|---|---|---|
| 30200 + role | one per room, at its most central free spot | room id × 128 + depth (0 start … 100 exit) |
| 30110 | a free floor spot | room id |
| 30111 | a goal spot (where Obsidian put a key / switch) | room id |
| 30112 / 30113 | the start / exit spot | room id |
| 30120 + kind | an entry (kind: 2 front = the start, 3 back = the exit room, 4 service = a small room or hallway far from the others, 5 roof / "over the fence" = a far outdoor area) | facing |
| 30130 | a light fitting | — |
| 30140 | a window (the game lets the player climb through; guards still can't) | — |
| 30150 | a point inside a crawl duct (the game lowers the ceiling there) | hallway room id |

The game has one class per marker number (`CW_ObsRoom00`…`19`, `CW_ObsSpot0`…`3`, `CW_ObsEntry2`…`5`, `CW_ObsLamp`); map-thing args don't survive Obsidian's output, so the type carries the kind and the angle carries the data.

### Industrial roles

| Role | Number | Room flags | Furniture |
|---|---|---|---|
| room | 0 | patrol, civ | — |
| yard | 1 | outdoor, patrol, civ | containers, pallets, dumpsters, pole lights |
| corridor | 2 | patrol | — |
| hall | 3 | patrol, civ, value, tech | shelving or benches (fab), pallets, crates |
| workshop | 4 | civ, tech | workbenches, scrap |
| plant | 5 | tech | generators or turbines (power plant), tanks, transformers |
| control | 6 | tech, people | code desks |

Room names depend on the job's variant ("the turbine hall" at a power plant, "the fab floor" at a fab plant). Repeats are numbered: "the second warehouse floor".

## 4. In the game

`CW_ObsSite.Generate`:

1. Reads the markers.
2. Converts every manual Doom door into a `CW_ObsDoor`. It opens and closes through the door's own faces, so it needs no tag. Guards open it, it shuts after 3 s, and the hack, bypass and breach logic comes from `CW_Door`.
3. Defuses the exits.
4. Turns sky floors into ground and zeroes floor damage.
5. Picks the insertion; the Intel entry choice picks the kind.
6. Adds lights: Obsidian's fittings, a few ceiling lights per room (some rooms stay dark), and pole lights in the yards.
7. Places extraction at every entry, then the crate.
8. Places objectives. They go by role flags, depth and distance from the insertion, spread over different rooms, with goal spots first.
9. Adds furniture at room spots, keeping doorways, the room's middle and the insertion clear.
10. Places guards: patrol loops through nearby rooms, posts at objectives and entries, and a supervisor. The count comes from the site's guard force.
11. Places bystanders.

The navigation graph is built as usual. Its furniture grid is now sized to the map, since Obsidian maps are about 7,000 units across.

### Map sizes (size tiers)

Each pool holds maps of three sizes (Obsidian seeds of 128 units):

| Maps | Tier | Size | Roughly | Must have (quality gate) |
|---|---|---|---|---|
| 01–04 | small | 16 | 1,500–2,500 units across | 4 rooms, 2 buildings, 2 entries |
| 05–08 | medium | 22 | 2,000–3,500 | 6 rooms, 3 buildings, 1 yard, 3 entries |
| 09–11 | large | 30 | 3,000–5,000 | 8 rooms, 4 buildings, 1 yard, 3 entries |

The city picks the tier from the site (`CW_City.SiteTier` in cityjobs.zs):
- substations are small; warehouses and salvage yards medium; docks, fab plants, power plants and industrial parks large, or medium if the property earns below its type's norm;
- strongholds are medium; neutral sites small (a quarter of them medium).

### Crawl ducts
Up to 2 of Obsidian's narrow service halls ("vent", else "access" halls) per map are marked as ducts. The game lowers their ceiling to 44 (the player crouches through; guards can't follow), gives them a grate ceiling and dims them. Guard patrols never span a duct.

### What the game checks and fixes on every pool map
- **Walkable areas.** Sectors are grouped by what the player can cross (step up to 32 with a jump, crouch headroom) and what a guard can (step 24, standing headroom, monster-blocking lines). The area holding most rooms is the site. Rooms outside it get no objectives, guards or bystanders.
- **Entries.** Every entry is tested with a player-sized probe: it must fit, not be in a duct or door, and have room to move in most directions. Otherwise it is moved to the nearest spot that works, or dropped. If none is left, the most central fitting spot in the site is used. On arrival the player is checked again (`OBSQA insert ...` in the log).
- **Doors.** Obsidian's switch-opened (tagged) doors become Corpo Wars doors too, since there are no switches.
- **Windows.** Invisible barriers between two indoor spaces and at window prefabs are opened for the player. Barriers at the map's scenery edge stay.
- **Ceilings.** No liquid flats anywhere; Obsidian used water and slime as light panels.
- **Furniture** keeps a player's width of passage all round, so corridors and narrow rooms stay open.
- `OBSQA <map> seed ...` in the log summarises it all: entries moved or dropped, unreachable rooms, objectives, ducts, windows opened.

## 5. Tuning and adding a site type

- **Look.** Edit the palette and room themes in `corpowars_sites.lua`. New textures go into the mod (`import_themes.py` for AD Cop ones); then re-run `obsidian_textures.py`.
- **Layout.** Edit the site's `style_list` (outdoors, big_rooms, hallways, steepness, windows, doors…) and the preset (`float_size`, modules).
- **A new site type:**
  1. Add a table to `CORPOWARS.SITES` (with its two map-name sets and roles).
  2. Add a preset.
  3. Add the site to `$Sites` in the launcher.
  4. Add its MAPINFO map names.
  5. Add a `PoolOfKit` entry and the role table in `obssite.zs`.
- **Testing:**
  - `+map CWI03 +cw_kitvariant 2 +cw_procseed 7` loads a pool map directly (with `-file CorpoWars_pool\cw_pool_industrial_CWI.pk3`).
  - `netevent cw_testkit 3` deploys the next city job on an industrial site (sv_cheats).
  - `netevent cw_guarddump` lists guard positions.
  - `cw_simverbose 1` prints the room positions.
- **Cloud QA rig:** `obsrun.sh` (Obsidian under Wine), `obslook.sh` (mission + screenshots), plan renders.
